## Invoice Settings page (`/settings/invoice`)

Add a dedicated settings page for two default textareas (Default Note, Default Bank Details), persist them per-user, and auto-fill them on the invoice **create** form (not edit — so existing invoices aren't clobbered).

### Storage: reuse the existing `UserPreference` model
The `userPreference` Inertia prop is already loaded on `invoices/create` (see `InvoiceController::create()`), so reusing `user_preferences` avoids a new model/migration/relationship.

1. **New migration** `database/migrations/<timestamp>_add_invoice_defaults_to_user_preferences_table.php`
   - `$table->text('default_note')->nullable()->after('company_logo');`
   - `$table->text('default_bank_account_info')->nullable()->after('default_note');`

2. **`app/Models/UserPreference.php`** — add `default_note`, `default_bank_account_info` to `$fillable`.

### Backend: new settings controller + route
3. **`app/Http/Controllers/Settings/InvoiceSettingsController.php`** (mirrors `UserPreferenceController` create-on-demand pattern):
   - `edit()` → `Auth::user()->preference ?? new UserPreference`, render `settings/invoice` with `['preference' => $preference]`.
   - `update(Request)` → validate `default_note` + `default_bank_account_info` as `nullable|string`, `fill()` + `save()`, `redirect()->back()`.

4. **`routes/settings.php`** (inside the `auth` group, after the preference block):
   - `Route::get('settings/invoice', [InvoiceSettingsController::class, 'edit'])->name('invoice.edit');`
   - `Route::post('settings/invoice', [InvoiceSettingsController::class, 'update'])->name('invoice.update');`
   - (Singular `invoice.*` names — avoids collision with the plural `invoices.*` resource names.)

### Frontend: new page + nav
5. **`resources/js/pages/settings/invoice.tsx`** — modeled on `preference.tsx`: `AppLayout > Head > SettingsLayout`, breadcrumbs `[{ title: 'Invoice Settings', href: '/settings/invoice' }]`, two `Textarea` fields (Default Note, Default Bank Details), `useForm` + `post('/settings/invoice', { preserveScroll: true })`, Save button + "Saved" `Transition`. No file upload → no `forceFormData` needed.

6. **`resources/js/layouts/settings/layout.tsx`** — add nav entry `{ title: 'Invoice', href: '/settings/invoice', icon: null }` (hardcoded string, consistent with the adjacent `preference` / `api-tokens` entries).

### Wiring: auto-fill defaults on create
7. **`resources/js/pages/invoices/components/invoice-form.tsx`**:
   - Extend the `UserPreference` interface (lines 74–80) with `default_note?: string` and `default_bank_account_info?: string`.
   - In the `useForm` initial state (lines 219–220), fall back to the user's defaults **only when creating** (the existing `isEditing = !!invoice` guard already distinguishes create vs edit):
     ```tsx
     notes: invoice?.notes || (!isEditing ? userPreference?.default_note ?? '' : ''),
     bank_account_info: invoice?.bank_account_info || (!isEditing ? userPreference?.default_bank_account_info ?? '' : ''),
     ```
   - No JSX changes — the existing Note / Bank Details textareas are already bound to `data.notes` / `data.bank_account_info`, so they'll display the defaults automatically.

### Test
8. **`tests/Feature/Settings/InvoiceSettingsTest.php`** (mirror existing settings/preference test pattern): assert the page renders for authed users, `default_note`/`default_bank_account_info` persist on POST, and guest gets redirected.
