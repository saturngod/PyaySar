# Pyaysar — Laravel 12 + React 19 + Inertia.js invoice app

## Commands

- `composer run setup` — full first-time setup: composer/npm install, `.env` copy, key:generate, migrate, build.
- `composer run dev` — runs **4 concurrent processes** (artisan serve, queue:listen, pail logs, vite). Use this, not `npm run dev`, for backend+frontend.
- `composer run dev:ssr` — same but with Inertia SSR instead of Vite.
- `composer run test` — clears config then runs `php artisan test` (PHPUnit/Pest). Use this, not `pest` directly, so the test env loads correctly.
- Single test / filter: `./vendor/bin/pest tests/Feature/ItemTest.php` or `./vendor/bin/pest --filter='items can be stored'`.
- `npm run types` — `tsc --noEmit` (typecheck). `npm run lint` (eslint --fix). `npm run format` (prettier on resources/).
- PHP format/lint: `./vendor/bin/pint`.

Recommended order before finishing a change: `pint` → `npm run types` → `composer run test`.

## Architecture / wiring

- **Auth is Laravel Fortify** (not Breeze/JetStream), with 2FA enabled (`app/Actions/Fortify/`, `routes/settings.php`). Most routes sit behind `['auth', 'verified']`.
- **Routes are split**: `routes/web.php` (app domain) `require`s `routes/settings.php` (profile/password/2FA/preference). Add new feature routes in `web.php`.
- **Inertia render paths are lowercase folders**: `Inertia::render('invoices/index')`, matching `resources/js/pages/invoices/index.tsx`.
- **All domain models are user-scoped**: query via `Auth::user()->invoices()/customers()/items()`, never global.

## Generated files — do not hand-edit

- `resources/js/routes/**` and `resources/js/wayfinder/index.ts` are **generated by Wayfinder** (`@laravel/vite-plugin-wayfinder`) and committed. After changing any Laravel route, run `npm run dev` (or `npm run build`) to regenerate the TypeScript route helpers before importing them.
- `/public/build` and `/public/hot` are build artifacts (gitignored).

## Frontend conventions

- **`@/` alias → `resources/js/*`** (tsconfig `baseUrl` + `paths`). Prefer `@/components/...`, `@/lib/...`.
- **React Compiler is enabled** (`babel-plugin-react-compiler` in vite.config.ts) — do not blanket code in `useMemo`/`useCallback`; let the compiler handle it.
- UI: shadcn "new-york" + Radix + Tailwind CSS 4 (CSS-first config in `resources/css/app.css`, **no `tailwind.config.js`**). Add components via `npx shadcn@latest add <name>`.
- TS strict mode; JSX runtime (`jsx: react-jsx`) — no `import React`.

## Design system (`DESIGN.md`)

- **`DESIGN.md` is the source of truth for all visual design** — colors, typography, spacing, radius, elevation, and component styling. Consult it before any UI/layout work.
- The theme is **Binance-inspired**: deep near-black canvas (`#0b0e11`) as the dark default, with **Binance Yellow (`#FCD535`)** as the single brand accent (primary CTAs, wordmark, brand headlines). Black text on yellow is the signature — never invert.
- **Dark is the app default** (set in `HandleAppearance.php`, `resources/js/hooks/use-appearance.tsx`, and `resources/views/app.blade.php`). Light theme maps to transactional surfaces. Both share the yellow primary and gray-blue hairlines.
- All theming flows through **semantic CSS variables** in `resources/css/app.css` (`--primary`, `--background`, `--card`, `--border`, `--ring`, …). shadcn components consume these tokens — **change values in `app.css`, not in component files**.
- **Typography**: Inter (BinanceNova substitute) via Bunny Fonts; `--font-mono` → IBM Plex Mono (BinancePlex substitute). Display weights stay 600–700; do not soften.
- **Trading semantics**: green `#0ecb81` (up) / red `#f6465d` (down) are price-direction signals only (exposed as `--color-trading-up` / `--color-trading-down`) — never use them for generic success/error states.
- **Don't** introduce a second brand color, add atmospheric gradients, or use yellow for body text / large fills. Radius is tight (6–12px); pill is reserved for top-of-page actions.

## Ownership & authorization

- Ownership is enforced **manually in controllers**, not via policies: `if ($model->user_id !== Auth::id()) abort(403);`. `app/Policies/ItemPolicy.php` is the only policy. Match this pattern in new controllers and cover it with `->assertForbidden()` tests (see `tests/Feature/ItemTest.php`).

## Business logic lives in services

- `app/Services/{InvoiceService,CustomerService,ItemService}.php` are the **single source of truth** for CRUD, invoice totals, status-history transitions, and avatar handling. Both HTTP controllers and MCP primitives depend on them — don't duplicate this logic in new entry points; extend the services.

## Testing quirks

- **Dev DB is MySQL** (`DB_DATABASE=invoices` in `.env.example`), but **`phpunit.xml` forces SQLite `:memory:`** with array caches and sync queue — no MySQL needed for tests.
- Pest 4. `RefreshDatabase` is auto-applied **only to `tests/Feature/`** via `tests/Pest.php`; `tests/Unit/` does not get it.
- Feature tests assert Inertia props with `AssertableInertia` (`->assertInertia(fn (Assert $page) => $page->component('items/index')->has('items.data', 3))`).

## PHP style (pint.json)

- Preset `laravel`, plus: `fully_qualified_strict_types`, `global_namespace_import` (import classes/functions/constants), `ordered_imports` (alpha), `no_unused_imports`. Imports must be fully-qualified or imported — no bare global class references.

## MCP server (`laravel/mcp`)

- The app exposes all features over MCP via `app/Mcp/Servers/PyaysarServer.php` (tools = writes/actions, resources = reads via URI templates like `invoice://invoices/{id}`, prompts = templates). Registered in `routes/ai.php` as **both transports**: `Mcp::web('/mcp', …)` behind `auth:sanctum`, and `Mcp::local('pyaysar', …)`.
- **User resolution**: the `App\Mcp\Concerns\ResolvesUser` trait resolves the Sanctum-authenticated user on the web transport; on the local (Artisan) transport there is no HTTP session, so it falls back to `MCP_LOCAL_USER_ID` (config `mcp.local_user_id`). Without either, the tool returns an error.
- **API gotcha**: tools that return `Response::structured(...)` must declare `handle(): Response|ResponseFactory` (and `use Laravel\Mcp\ResponseFactory;`); `Response::text()`/`Response::json()` return `Response` only.
- Test MCP primitives with the package's helper: `PyaysarServer::actingAs($user)->tool(Tool::class, [...])` (see `tests/Feature/Mcp/PyaysarServerTest.php`).
